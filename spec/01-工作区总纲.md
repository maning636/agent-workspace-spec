# 01 · 工作区总纲

## 1. 核心命题

> **CLI 是运行时，文件夹是智能体。**

智能体的本体不是某个模型，而是"一个组织良好的工作目录 + 一个进入该目录的
CLI 会话"。模型会话结束后即失忆，因此智能体的**一致性、记忆与纪律必须外化
到文件系统**，由每次会话开机时重新加载。

## 2. 分层模型

```
┌─────────────────────────────────────────────┐
│  L1 运行时（Runtime）                        │
│  agent CLI 本身：Claude Code / Codex /        │
│  Kimi Code / OpenCode…… 不属于本规范约束对象  │
├─────────────────────────────────────────────┤
│  L2 制度（AGENTS.md）                        │
│  人设、职责、工作流、目录约定、禁止事项        │
├─────────────────────────────────────────────┤
│  L3 技能（skills/*/SKILL.md）                │
│  按需加载的能力包；一个技能 = 一类可复用任务    │
├─────────────────────────────────────────────┤
│  L4 确定性工具（scripts/）                   │
│  不许模型即兴发挥的部分：校验、转换、批量操作   │
├─────────────────────────────────────────────┤
│  L5 记忆与物料（台账 / 素材 / 产出）           │
│  跨会话状态、输入、输出                        │
└─────────────────────────────────────────────┘
```

【必须】五个层次各司其职，不得互相越界写入：制度不写进技能，技能不内嵌
一次性业务逻辑，业务逻辑不下沉到台账。

【应当】一个智能体一个主文件夹，文件夹名即智能体名。

## 3. 标准目录骨架

```
<智能体名>/
├── AGENTS.md              # L2 制度（必需）
├── skills/                # L3 技能包（至少一个）
│   └── <技能名>/
│       └── SKILL.md
├── scripts/               # L4 确定性工具
├── 素材/                   # L5 输入：待处理的原材料
├── 产出/                   # L5 输出：交付物
└── 台账.md                 # L5 跨会话状态
```

【必须】`AGENTS.md` 是唯一入口：CLI 与人读到的第一份文件。
【必须】输入与输出物理分离（`素材/` 与 `产出/`），禁止 agent 改写素材。
【应当】空目录用 `.gitkeep` 占位，保证克隆后骨架完整。

## 4. 一致性的来源

智能体行为可预测，靠的是三条加载链：

1. **开机加载**：CLI 进入目录 → 读 `AGENTS.md` → 获得人设与边界；
2. **按需加载**：遇到匹配任务 → 读对应 `SKILL.md` → 获得操作流程；
3. **续档加载**：开工前 → 读 `台账.md` → 恢复上一次会话的进度与承诺。

【必须】任何"下次还要这样做"的经验，落地到 L2/L3/L4 的文件里，而不是
期待模型记住。会话记忆不构成规范的一部分。

## 5. 与上游标准的关系

| 本规范 | 上游标准 | 关系 |
|---|---|---|
| L2 | [agents.md](https://agents.md) | 直接采用其格式约定，本文补充章节模板 |
| L3 | [agentskills.io](https://agentskills.io) | 完全兼容 SKILL.md 规范，见 03 篇 |
| L4/L5 | 无上游 | 本规范的实践增量 |

## 6. 反模式速查

- ❌ 把所有指令堆进一个巨型 AGENTS.md（应拆分：通用→L2，可复用流程→L3）
- ❌ 素材和产出混在一个目录里靠文件名区分
- ❌ 关键经验只留在聊天记录里，下一场会话全部重来
- ❌ 让模型每次凭记忆手敲同一套转换脚本（应固化进 scripts/）
- ❌ 一个文件夹塞多个不同人设的智能体（应一夹一体）
