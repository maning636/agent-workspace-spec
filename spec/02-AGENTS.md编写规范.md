# 02 · AGENTS.md 编写规范

`AGENTS.md` 是写给 agent 的 README：一个固定、可预测的位置，放模型每次
开机都需要的上下文。格式遵循 [agents.md](https://agents.md) 开放标准。

## 1. 定位

- **读者是模型，不是人**：人读 README，agent 读 AGENTS.md。
- **放"每次会话都需要"的内容**：只写会改变行为的东西；偶发操作交给技能。
- 【必须】放在工作区根目录；【应当】控制在 150 行以内——超出即拆分。

## 2. 必备章节模板

```markdown
# <智能体名>

## 身份与职责
你是谁、为谁服务、只做什么、不做什么。
（例：你是"周报导写员"，只负责把素材/周报/ 下的原始记录
  加工成周报初稿；不负责排版与发送。）

## 目录约定
- 素材/     输入，只读
- 产出/     输出，只增不改
- 台账.md   开工前必读，收工时必须更新
- scripts/  优先使用现成脚本，不要手写等效逻辑

## 工作流
1. 读台账.md 恢复上下文
2. 处理任务（复杂流程查 skills/）
3. 交付物写入 产出/，按 05 篇命名规则命名
4. 更新台账.md（做了什么、待办、遗留问题）

## 命令
- 校验产出：`python scripts/check_output.py`
- （其他常用命令）

## 禁止事项
- 不修改 素材/ 下任何文件
- 不编造台账中不存在的进度
- 产出未经校验脚本通过不得宣告完成
```

【必须】包含：身份与职责、目录约定、工作流、禁止事项 四节。
【应当】包含：命令一节（setup/build/check 等可执行入口）。

## 3. 层级覆盖（渐进披露）

AGENTS.md 支持目录级覆盖：子目录可放置自己的 AGENTS.md，agent 进入该
目录工作时，子目录规则叠加在根规则之上。

【必须】子目录 AGENTS.md 只写**增量约束**，不重复根文件内容。
【应当】当某子目录的约束超过 20 行，或形成独立流程时，升级为该目录的
独立技能（见 03 篇），而不是继续加长。

```
工作区/
├── AGENTS.md              # 全局：人设、总工作流
└── 素材/客户来稿/
    └── AGENTS.md          # 增量：来稿脱敏要求、保密边界
```

## 4. 写法纪律

- 【必须】指令用祈使句 + 可验证结果（"产出必须通过 check_output.py"，
  而非"注意质量"）。
- 【必须】禁止事项成节集中列出，逐条可判定违反与否。
- 【应当】一个知识点只出现在一个层次：全局惯例→AGENTS.md，
  可复用流程→SKILL.md，机械操作→scripts/。
- 【可以】文末附"变更记录"三行以内，说明本文件最近为何修改。

## 5. 反模式

- ❌ 复制粘贴 README 内容凑数——重复信息会漂移，模型无所适从
- ❌ 写成散文随笔（"我希望你像一个经验丰富的老编辑那样……"无行为约束力）
- ❌ 堆放一次性任务（那属于台账或当次会话，不属于制度）
- ❌ 子目录 AGENTS.md 大段复制根文件（违反增量原则）
