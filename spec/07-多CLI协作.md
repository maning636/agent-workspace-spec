# 07 · 多 CLI 协作

本规范默认单智能体单文件夹。当同时使用 2-3 个 CLI（如 Claude Code +
Codex + Kimi Code）时，协作的关键是**上下文隔离 + 文件化交接**，
而不是让某个"主 agent"把所有上下文攒在一个窗口里。

## 1. 两种协作架构

| | 主 agent 模式 | 工作区协作模式（本规范） |
|---|---|---|
| 协调状态 | 在主 agent 上下文窗口内 | 在共享文件（台账/交接单）里 |
| 通信方式 | 子 agent 结果摘要回传 | 产物落盘 + 交接文件 |
| 会话寿命 | 随主会话结束而失忆 | 跨会话持久（每体各有台账） |
| 适用任务 | 强耦合、需频繁来回试探 | 松耦合、可独立交付的批次任务 |

【应当】判断标准：子任务之间共享同一份"进行中的工作状态"→ 主 agent
模式；子任务各自有明确的输入与交付物 → 工作区协作模式。

## 2. 分工原则

【必须】

- **一体一夹**：每个 CLI 一个工作区文件夹，各有自己的
  AGENTS.md（人设可以不同）与台账；
- **按产物分工**：分工单位是"谁交付什么"，不是"谁比较聪明"；
  同一文件夹禁止两个不同人设的 CLI 混写。

【应当】按比较优势分配，例如：

- CLI-A（长上下文）：通读全部素材、做调研综述 → 产物进共享素材区
- CLI-B（强编码）：维护 scripts/、跑批量处理 → 各智能体的校验工具
- CLI-C（文风好）：面向人的成稿 → 消费 CLI-A 的综述产出

## 3. 交接协议

体与体之间只通过文件交接。交接点放在 `素材/`（往下游供给）或
约定的共享目录，交接信息记入**交接单**：

```markdown
# 交接单（位于产出方工作区：产出/交接/YYYY-MM-DD-主题.md）

## 交付物
- 文件：产出/综述/2026-10-31-竞品综述.md
- 状态：已完成，check 脚本通过

## 下游动作
- 请 CLI-C 据此撰写报告初稿，模板见其 skills/report/SKILL.md

## 注意
- 第 3 节数据为估算值，正文引用时须标注
```

【必须】交接单五要素：交付物路径、状态、下游动作、注意事项、日期。
【必须】消费方开工时先读交接单再动工；对交付物的疑问回写交接单，
不口头约定。

## 4. 人的角色

多 CLI 模式下，人保留三个不可让渡的职责：

1. **分派**：决定哪个体接哪个任务（写进对方台账）；大型变更先立项
   （Vision 定不变哲学 + BuildSpec 定本期范围，阶段 ≤3）并经人批准，
   再拆给各体——spec 只给当期，agent 不需要知道全盘规划；
2. **验收**：交付物经校验脚本 + 人工抽检后才算完成；
3. **仲裁**：两个体的产出冲突时，以台账决策记录为准，无记录由人裁决。

## 5. 何时升级到调度层

出现以下任一情况，再考虑看板/daemon 类平台（Multica 等）：

- 需要**无人值守**：定时任务、夜间批处理、失败自动重试；
- 需要**跨机器**并行运行；
- 需要 per-run 的成本核算与执行日志审计。

台账与交接协议均基于纯文件，可原样被调度层读取——升级不需要重写
工作区，只需把"人做分派"换成"平台做分派"。

## 6. 反模式

- ❌ 让一个主 agent 转述所有体的产出（摘要损耗 + 上下文爆炸）
- ❌ 两个 CLI 写同一个文件夹（人设漂移、台账互相覆盖）
- ❌ 体与体通过聊天记录互相@（会话结束即失忆，必须走交接单）
- ❌ 过早引入调度平台：3 个以内 CLI、人工可分派时，文件协议足够
