# 05 · 素材与产出目录

输入与输出物理分离是本规范的第一硬约束：agent 可以消费素材，
但**永不修改素材**；产出只增不改，形成可审计的交付流。

## 1. 分区定义

```
素材/    输入。原材料、来稿、采集数据、参考资料。
         agent 只读。【必须】任何工作流不得写入此目录。
产出/    输出。交付物。agent 只增。【应当】按批次子目录组织。
scripts/ 工具。见 04 篇。
```

【必须】纠错素材的唯一合法路径是：把修正后的版本作为**新文件**放入
`素材/`（或由人替换），并视需要记入台账。agent 不得原地改写素材后
冒充"原素材"。

## 2. 产出组织

【必须】批次化：每项交付一个子目录或带批次前缀，永不覆盖旧批次。

```
产出/
├── 周报/
│   ├── 2026-W44-周报.md
│   └── 2026-W45-周报.md
└── 客户报告/
    └── 20261031-某某项目-v2.md      # v2 是新文件，v1 保留
```

【必须】命名含可排序的时间要素（`YYYY-MM-DD` / `YYYY-Www` / `YYYYMMDD`）。
【应当】文件名能脱离上下文自解释：`日期-主题-版本`，不用"最终版""新建
文档(3)"这类名称。修订走新文件，不走路覆盖。

## 3. git 取舍

【必须】进版本库：`AGENTS.md`、`skills/`、`scripts/`、`台账.md`、
`素材/` 中可公开的原始材料。
【应当】不进版本库（.gitignore）：大体积二进制素材、含敏感信息的
客户材料、一次性中间产物。确有保留价值的产出可单独建归档分支或仓库。
【可以】素材与产出分库管理（素材库私有、规范库公开）。

## 4. 反模式

- ❌ 素材与产出同目录，靠文件名前缀区分（agent 迟早写错方向）
- ❌ 直接覆盖上一版产出（丢失交付历史，无法回溯"当时给了客户什么"）
- ❌ agent "顺手优化"了素材里的错别字（输入被污染，溯源断裂）
- ❌ 命名无时间要素，目录排序全靠记忆
