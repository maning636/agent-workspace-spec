# 04 · 脚本与确定性工具

`scripts/` 存放**不许模型即兴发挥**的逻辑。凡是"结果可以机械判定对错"
的操作，都应该从模型的自由发挥中剥离，固化成脚本。

## 1. 什么进 scripts

【必须】进入 scripts/ 的四类操作：

1. **校验类**：产出完整性、格式、数值一致性检查（如 `check_output.py`）
2. **转换类**：格式转换、重命名、批量搬运（如 `convert_md2docx.py`）
3. **采集类**：固定数据源的抓取与落盘（如 `fetch_prices.py`）
4. **清理类**：幂等的归档、去重（如 `archive_old.py`）

【必须】留在模型侧的三类操作：判断与取舍（写哪段、删哪段）、
自然语言加工、无固定规则的一次性决策。

判据一句话：**给两个不同模型跑同一个脚本，结果必须一致；
给同一个模型跑两次自由发挥，结果未必一致——前者进 scripts/。**

## 2. 脚本纪律

【必须】

- **幂等**：同一输入重复执行，结果一致、无副作用累积；
- **退出码**：成功 `0`，失败非 `0` 并向 stderr 输出一行中文原因；
- **自包含**：只依赖标准库或 requirements.txt 中声明的包，不依赖
  agent 会话中的临时状态；
- **可试运行**：破坏性操作（删除、覆盖）必须支持 `--dry-run` 并默认开启。

【应当】

- 每个脚本头部 3-5 行注释：用途、输入、输出、退出码含义；
- 优先 Python 单文件，通用工具优先 CLI 参数而非改代码；
- AGENTS.md 的"命令"一节登记常用脚本及其用法。

## 3. 调用契约

【必须】agent 调用脚本后**必须检查退出码**，非 0 时把 stderr 内容
作为失败原因处理，禁止把失败重述为成功。

【应当】脚本的输出是机器可判定的（PASS/FAIL + 逐项明细），
让模型能直接依据输出修复，而不是再猜一遍。

## 4. 反模式

- ❌ 每次让模型手敲同一套转换逻辑（应固化、复用、可审计）
- ❌ 脚本静默吞错、永远返回 0（模型会误判成功）
- ❌ 校验脚本和被校验对象由同一次会话即兴生成（校验必须先于产出存在）
- ❌ 破坏性脚本没有 dry-run，一次误跑清空 产出/
